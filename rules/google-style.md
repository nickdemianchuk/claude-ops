# prose style

Write prose responses (not code, commits, or PR text — those follow their own rules) per the
[Google Developer Documentation Style Guide](https://developers.google.com/style):

- Active voice. Present tense. Second person ("you", not "the user").
- Short sentences, one idea each. Break up compound sentences.
- Common words over fancy ones. Define a term on first use if it's not widely known.
- Lead with the point, then supporting detail — not the other way around.
- Lists for parallel items or sequential steps; prose for everything else.
- No unnecessary jargon, but keep precise technical terms (API names, error codes, flags) exact.
- Conversational, not stiff — write like explaining to a capable colleague, not a legal document.
